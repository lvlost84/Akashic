# 이미지 삽입 기능 설계 (아카식 v2.1 후보)

작성일 2026-11-17 · 기준 코드 v2.0.6 · 상태: **구현됨(v2.1.0, GUI 수동 확인 전)**

## 1. 의도와 이유
아카식은 문서가 DB 파일 하나로 끝나는 오프라인 마크다운 노트 앱이다. 여기에 이미지를 넣고 싶다. 이미지가 많아져도 DB와 동기화 저장본이 부풀지 않도록 **구글의 WebP 압축**으로 용량을 줄여 저장한다. 사용자가 정한 것: **DB에 저장**, **편집기에서 줄 높이를 키워 그림을 그리는 방식(A)**.

## 2. 목표 / 비목표 / 안티목표
**목표**
- 이미지를 붙여넣기(Ctrl+V)·파일 끌어놓기·메뉴로 문서에 넣는다.
- 넣는 즉시 WebP로 줄여 DB에 저장한다(긴 변 최대 1600px, 품질 80이 기본, 설정에서 변경).
- 편집기에서 "보이는 대로" 표시한다. 커서가 그 줄에 있으면 원문이 보인다(표·가로줄과 같은 규칙).
- 같은 그림은 한 번만 저장한다. 쓰지 않는 그림은 정리한다.
- Markdown 내보내기에서 이미지가 살아 있다. 백업·동기화는 지금 방식 그대로 된다.

**비목표(이번 버전)**: 이미지 편집(자르기·회전·크기 조절 핸들), 외부 URL 이미지 자동 내려받기(오프라인 앱), GIF 애니메이션(첫 프레임만), 가져오기(.md) 때 상대경로 그림 자동 흡수, 클릭해서 확대.

**안티목표**: 그림이 많은 문서가 느려지는 것, 이미지 때문에 동기화가 눈에 띄게 느려지는 것, 문서를 열 때마다 모든 그림을 디코딩하는 것, 기존 문서·DB가 깨지는 것.

## 3. 제약
- 기존 구조 유지: 본문은 `TextEdit` 하나, `md.rs`가 줄 단위 `LayoutJob`을 만들고 `render.rs`가 투명 글자 위에 그린다(표·가로줄·체크박스와 같은 방식).
- 줄 높이는 `TextFormat.line_height`로 줄 수 있다(`md.rs:63`). 이를 이용해 이미지 줄 높이를 그림 높이로 키운다.
- DB 스키마 버전 2 → 3. 변경 카운터 트리거(`meta.rev`)는 새 테이블에도 달아야 닫을 때 동기화가 놓치지 않는다.
- `md::build`는 DB를 모른다 → 그림 크기는 본문 텍스트 안에 담는다(아래 4.1).
- 한 파일 HTML 같은 제약은 이 프로젝트와 무관. 빌드 CI(10분대)와 실행 파일 크기(+0.3~0.5MB 예상)는 허용.
- egui는 클립보드 이미지를 못 읽는다 → 붙여넣기용 크레이트 필요.

## 4. 접근 방식
검토한 방법: **A** 편집기 줄 높이 확장 + 그림 그리기, **B** 옆 미리보기에만 표시, **C** 이미지를 DB 밖 폴더에 저장.
- B는 "보이는 대로 편집"이라는 앱 방향과 어긋난다.
- C는 문서가 DB 하나라는 단순함과 동기화 일관성을 잃는다.
- **사용자가 A + DB 저장을 선택했다.**

### 4.1 본문 문법
`![대체글](img:해시 가로x세로)` 한 줄(그 줄에 이것만 있을 때만 이미지 블록).
- `해시` = 디코딩한 RGBA 픽셀과 크기의 SHA-256 앞 16자리(16진수). 같은 그림을 두 번 붙여도 한 번만 저장된다. *(내 결정: 압축본이 아니라 픽셀로 해시해 품질 설정이 달라도 같은 그림은 하나로 합쳐진다.)*
- `가로x세로` = 저장된 이미지의 원래 크기. 레이아웃이 DB 없이 줄 높이를 정하기 위한 값이다. *(내 결정.)*
- 대체글은 넣을 때 파일 이름(확장자 제외)으로 채우고 60자로 자른다.
- 줄 안에 다른 글이 섞인 `![…](img:…)`는 이미지 블록이 아니라 일반 글자로 둔다.

### 4.2 DB (스키마 v3)
```
images(hash TEXT PRIMARY KEY, webp BLOB NOT NULL, w INTEGER NOT NULL,
       h INTEGER NOT NULL, created INTEGER NOT NULL)
```
- 마이그레이션: `migrate()`에서 v2 → v3으로 테이블 생성(기존 문서는 그대로).
- `rev` 트리거: images insert/delete에 추가(`REV_SQL`).
- API: `put_image(hash, webp, w, h)`(이미 있으면 무시), `get_image(hash) -> Option<(Vec<u8>, w, h)>`, `image_stats() -> (개수, 총 바이트)`, `prune_images() -> 지운 개수`.
- 큰 BLOB은 문서 쿼리에서 읽지 않는다(별도 테이블이라 목록·검색에 영향 없음).

### 4.3 가져오기·압축 파이프라인(백그라운드 스레드)
1. 입력 원천: 클립보드 이미지(`arboard`), 끌어놓은 파일(`app.rs`의 드롭 처리에서 확장자 png/jpg/jpeg/bmp/gif/webp이면 이미지로 분기, 나머지는 기존 가져오기), 메뉴 "이미지 삽입…"(rfd 파일 선택).
2. 디코딩(`image` 크레이트, 필요한 형식만 켬) → 긴 변이 최대 크기보다 크면 축소(Lanczos3) → 알파가 있으면 알파 유지.
3. `webp` 크레이트(libwebp)로 손실 압축(품질 기본 80). 알파가 없고 그림이 아주 작은(예: 256px 이하 UI 캡처) 경우 무손실이 더 작으면 무손실을 쓴다. *(내 결정: 둘 중 작은 쪽 저장.)*
4. UI 스레드로 결과를 보내면 DB에 저장하고, 입력 당시 커서가 있던 줄 **다음 줄**에 `![…](img:…)` 줄을 삽입한다(앞뒤 빈 줄 자동 보정). 처리 중에는 상태바에 "이미지 처리 중…". 처리 중 문서를 바꿨으면 원래 문서 id에 삽입하지 않고 취소한다. *(내 결정: 안전하게 취소.)*
5. 원본이 너무 크거나(예: 100MB 초과, 디코딩 가능한 픽셀 수 제한 초과) 실패하면 알림만 하고 문서는 건드리지 않는다.

설정(옵션 창): 최대 크기(800/1200/1600/2400px), 품질(60~95). `Config`에 `img_max`, `img_quality` 추가(없으면 기본값).

### 4.4 표시 (md.rs + render.rs)
- `scan_blocks`에 `BlockKind::Image { alt, hash, w, h }` 추가(한 줄 블록, `start == end`).
- `md::build`: `hide_syntax`이고 커서가 그 줄에 없으면 줄 글자를 투명·아주 작게 하고 `line_height`를 **표시 높이**로 준다. 표시 폭 = `min(w, 본문 폭)`, 높이는 비율대로, 최대 700px 논리 단위(내 결정). 커서가 그 줄에 있거나 `hide_syntax`가 꺼져 있으면 원문을 그대로 보인다.
- `render::paint`: 이미지 블록은 화면에 보이는(클립 영역과 겹치는) 것만 텍스처를 만든다. 가운데 정렬, 둥근 모서리 약간, 테두리는 테마의 표 격자색. DB에 해시가 없으면 "이미지를 찾을 수 없음" 회색 상자.
- 텍스처 캐시: 해시 → 텍스처, 최대 32개·약 64MB(LRU). 디코딩은 화면에 보일 때 UI 스레드에서(최대 1600px WebP는 수 ms). 한 프레임에 새로 디코딩하는 수를 2개로 제한해 스크롤이 끊기지 않게 한다.
- `blocks_cached`는 본문 해시로 캐시되므로 이미지 블록도 같은 캐시를 탄다.
- 링크 처리: `![…](img:…)`가 인라인 링크 파서에 걸려 클릭 시 외부 열기가 되지 않도록 `img:` 스킴을 `is_external_target`(md.rs:638)에서 제외한다.

### 4.5 정리(참조 없는 이미지 삭제)
- `prune_images`: 모든 문서(휴지통 포함) 본문에서 `img:해시`를 모아, 어디서도 쓰이지 않는 이미지를 삭제한다.
- 실행 시점: 문서 영구 삭제·휴지통 비우기 후, 옵션 창의 "사용하지 않는 이미지 정리" 버튼. 앱 종료·시작 때는 돌리지 않는다(본문 전체를 읽는 비용). *(내 결정.)*
- 옵션 창에 "이미지 N개 · X MB"를 표시한다(작은 부가 기능, 내 결정).
- 휴지통 문서의 이미지는 복원될 수 있으므로 보존된다.

### 4.6 내보내기 (export.rs / export_ui.rs)
- 내보내는 문서에 `img:해시`가 있으면 내보내기 폴더 아래 `images/해시.webp`로 파일을 꺼내고 본문을 `![대체글](상대경로/images/해시.webp)`로 바꾼다. 문서가 하위 폴더에 있으면 `../` 깊이를 맞춘다.
- 이미지는 변환 없이 WebP 그대로(다시 압축하지 않는다). 뷰어 호환 문제가 있는 사용자를 위한 PNG 변환 옵션은 이번에는 넣지 않는다.
- 내보내기 스레드가 DB를 읽는 방식은 기존 구조(`export_ui.rs`)를 따른다.

### 4.7 동기화·백업과의 관계
- 이미지는 DB 안에 있으므로 스냅샷·조각 업로드·복원이 기존 그대로 동작한다. 단, 저장본 크기가 커진다.
- 구현 후 기존 `measure_chunk_churn` 방식으로 "그림 추가 후 바뀐 조각 수"를 측정해 DEVLOG에 기록한다(BLOB은 새 페이지에 쓰여 조각 변화가 작을 것으로 예상하지만 실측으로 확인).
- 구버전(v2) 저장본을 복원하면 `migrate()`가 images 테이블을 만든다(v2.0.5의 복원 후 migrate 호출로 이미 처리됨).
- 구버전 아카식(v2.0.x)이 v3 DB를 열면 `ver > SCHEMA_VERSION` 검사로 거부한다(기존 동작). 자동 업데이트가 있어 실제 영향은 작다.

## 5. 의존성 추가(예상)
- `webp`(libwebp 바인딩, C 컴파일 — rusqlite bundled로 이미 C 빌드 환경 있음)
- `image`(default-features 끄고 png, jpeg, bmp, gif, webp만)
- `arboard`(클립보드 이미지, Windows에서 동작)
- 라이선스 고지: 빌드가 만드는 `LICENSE.md`(build.rs의 cargo metadata)에 자동 포함되는지 확인.

## 6. 테스트 계획
- DB: put/get/중복 저장, v2→v3 마이그레이션, 트리거로 `rev` 증가, `prune_images`(휴지통 문서 보존 포함).
- md: `scan_blocks`가 한 줄 이미지만 블록으로 인식, 줄 높이 계산, 인라인 섞인 경우 일반 글자, `img:` 링크가 외부 링크로 취급되지 않음.
- 압축: 알파 유지, 축소 후 가로세로 비율, 같은 픽셀 → 같은 해시, 손상된 파일 실패 처리.
- 내보내기: 경로 치환·폴더 깊이, 같은 이미지 여러 문서에서 한 번만 파일로.
- 수동 확인(GUI): 붙여넣기·드롭·커서 진입 시 원문 표시, 긴 문서 스크롤 성능, 창 폭 변경 시 높이 재계산, 다크/라이트.

## 7. 위험과 구현자가 확인할 것
- **줄바꿈 위험:** 투명하게 접은 원문 줄이 길어 여러 행으로 감기면 행마다 큰 줄 높이가 적용될 수 있다. 접은 글자를 아주 작은 글꼴로 하고 대체글을 60자로 제한하지만, 좁은 창에서 직접 확인해야 한다. 필요하면 대체글 길이 제한을 더 줄이거나 접은 줄에서 대체글을 글자 모양에서 뺀다.
- **높이 재계산:** 본문 폭이 바뀌면(창 크기·목차 패널) `build`의 `wrap` 인자로 높이가 다시 계산되는지 확인한다.
- **찾기·상태바:** 줄 수·글자 수는 원문 기준이므로 이미지 줄이 한 줄로 센다. 찾기 일치 표시 위치는 투명 글자와 무관하게 동작해야 한다.
- **IME·되돌리기:** 이미지 줄 삽입은 `TextEdit`의 정상 편집 경로로 넣어 Ctrl+Z가 줄 삽입만 되돌리게 한다(DB의 그림은 정리 전까지 남음).
- **메모리:** 큰 이미지(디코딩 후 수십 MB)는 최대 크기로 축소한 뒤 텍스처를 만든다. 캐시 한도를 넘지 않는지 확인한다.
- **버전:** 작업공간 기준이 v2.0.6이다. 구현이 끝나면 v2.1.0으로 올리고 `Cargo.toml`, DEVLOG, README, 개선목록을 갱신한다.

## 8. 구현자에게 맡기는 것
모듈 분리(예: `src/img.rs` 압축·캐시, `db.rs` 이미지 API, `src/app/image_ui.rs` 입력·옵션), 텍스처 캐시 자료구조 세부, 둥근 모서리·테두리 스타일 값, 상태바 문구, 테스트 세부 케이스.

## 9. 내가 정한 것(확인용)
1. 해시는 픽셀 기준 16자리, 크기를 본문에 함께 적는다.
2. 이미지 블록은 "그 줄에 이것만 있을 때"만 인정한다.
3. 손실/무손실 중 작은 쪽을 저장한다.
4. 처리 중 문서가 바뀌면 삽입을 취소한다.
5. 정리는 영구 삭제·휴지통 비우기·수동 버튼에서만 실행한다.
6. 표시 최대 높이 700px, 텍스처 캐시 32개/64MB.
7. 내보내기는 WebP 그대로, PNG 변환 옵션 없음.
