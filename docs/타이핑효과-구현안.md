# 타이핑 효과 구현안 (v2.25.1 기준으로 고침)

프로젝트 폴더는 **현재 실행 중인 폴더**다(PC마다 경로가 다르므로 절대경로를 쓰지 않는다). Rust + eframe/egui 0.37 + rusqlite, Windows. 답변·주석·화면 글은 **한국어**.
커밋·푸시·버전 올리기는 사용자가 말할 때만 한다. 작업 전에 방식을 먼저 말하고, 코드 수정은 그 뒤에 한다.

## 1. 무엇을 만드나
편집창(본문)에서 글을 칠 때의 효과. 옵션으로 끄고 켠다.

1. **깜박임 조절**: 한글 조합 중 커서가 번쩍거리는 것이 보기 싫다는 요청이 출발점이다. 깜박임을 끌 수 있게 한다.
2. **부드러운 커서**: 커서가 한 칸씩 튀지 않고 이전 위치에서 새 위치로 약 80ms 동안 미끄러진다. 깜박임은 켜짐/꺼짐이 딱딱하게 바뀌지 않고 서서히 흐려졌다 선명해진다.
3. **글자가 스며드는 효과**: 새로 친 글자가 약 120ms 동안 투명하게 시작해 선명해진다.

## 2. 정해진 결정 (바꾸지 말 것)
- 옵션 이름 "타이핑 효과", 선택지 **끔 / 커서만 / 커서+글자**(`cfg.typing_fx`: 0/1/2). **기본값은 "끔"**. 별도 체크박스 "커서 깜박임"(`cfg.caret_blink`, 기본 켬)은 효과가 "끔"일 때도 적용한다(egui 기본 커서의 깜박임).
- **새 크레이트를 추가하지 않는다**(직접 의존성 10개 이하). 조사 결과(2026-11-24): egui용 부드러운 캐럿 크레이트는 없고, `egui_animation`(이징만, `emath::easing`과 겹침)·`egui_text_animation`(표시용 글자 효과)·`eazy`(범용 트윈)는 쓸 이유가 없다.
- **egui 내장 기능을 쓴다**(직접 만들지 않는다):
  - 커서 미끄러짐: `ctx.animate_value_with_time(id, 목표, 시간)`. 값이 바뀌면 그 시간 동안 선형 보간하고 진행 중에만 자동으로 다시 그린다.
  - 곡선: `emath::easing`(예: `exponential_out`).
  - 깜박임 끄기·간격: `Visuals::text_cursor`의 `blink`·`on_duration`·`off_duration`.
- 글자 효과는 **글자 배치를 다시 계산하지 않는다**. 새로 친 글자 위에 편집창 배경색 사각형을 덮고 그 투명도를 1→0으로 줄인다.
- 표·코드 블록 안(`md::Block`은 **줄 번호** 범위 `start..=end`)에서는 글자 효과를 건너뛴다(배경색이 달라 어긋나 보임).
- 화면을 다시 그리게 하는 것은 **애니메이션이 진행되는 동안만**(깜박임 서서히 처리는 포커스가 있을 때만 약 50ms 간격).

## 3. 단계 (한 단계씩 시험·빌드 후 다음으로)
1. **깜박임 옵션**: `Config.caret_blink`(기본 true)와 옵션 체크박스. 본문 편집창 영역에서만 `ui.visuals_mut().text_cursor.blink`에 반영(다른 입력칸에 영향 없게 스크롤 영역 안에서 설정).
2. **부드러운 커서**(`typing_fx >= 1`): egui 기본 커서를 숨기고(`text_cursor.stroke = Stroke::NONE`, 편집창 영역 안에서만) 직접 그린다. 위치는 **글자 배치 안의 좌표**(`pos_from_cursor`)로 보간하고 그릴 때 `galley_pos`를 더해, 스크롤해도 어긋나지 않게 한다. 줄이 바뀌면(y가 달라지면) `animate_value_with_time(..., 0.0)`으로 보간을 건너뛰고 바로 이동한다.
3. **글자 스며들기**(`typing_fx == 2`): 본문이 1~20자 늘고 커서가 그만큼 움직였으면 방금 친 글자 범위를 `(시작, 끝, 시각)`으로 목록에 넣고, 그릴 때 배경색 덮개 투명도를 `reveal_cover`로 줄인다.
4. 문서(DEVLOG·도움말·이 문서) 갱신.

## 4. 순수 함수 (`src/typefx.rs`, 시험 가능)
```rust
/// 깜박임: 마지막 입력 후 시간 since_input(초)로 커서 선명도 0.0~1.0. 입력 직후 0.5초는 1.0.
/// blink=false면 항상 1.0.
pub fn blink_alpha(since_input: f32, blink: bool) -> f32;
/// 글자를 친 뒤 경과 시간 age(초)로 덮개 투명도 1.0 → 0.0 (120ms, emath 이징).
pub fn reveal_cover(age: f32) -> f32;
/// 이번 프레임에 "방금 친 글자" 범위. 길이가 1..=20자 늘고 커서가 그만큼 오른쪽으로 옮겨졌을 때만 Some((시작, 끝)).
pub fn typed_range(prev_len: usize, new_len: usize, prev_cursor: usize, new_cursor: usize) -> Option<(usize, usize)>;
```
시험: `blink_alpha` 입력 직후 1.0·범위 안·blink=false면 1.0 / `reveal_cover` 0초 1.0·120ms 이후 0.0·단조 감소 / `typed_range` 한 글자 입력·21자 이상(붙여넣기)은 None·삭제는 None·커서가 안 움직였으면 None.

## 5. 화면 연결 (`body_editor`, `src/app.rs`)
이미 있는 값: `out.galley`, `out.galley_pos`, `self.cursor_idx`, `self.body_composing`, `bg`(편집창 배경), `editable`, 타자기 모드용 `typewriter`.
- **한글 조합**: egui는 조합 중인 글자를 본문에 넣고 그 구간을 **선택**으로 잡는다. 그래서 조합 중(`body_composing`)에는 선택 끝(`max(primary, secondary)`)을 커서로 본다(`[[` 후보 `link_suggest_ui`와 같은 방식).
- 조합 중 음절이 바뀌어도 본문 길이는 그대로이므로 `typed_range`는 None이다 → 같은 음절을 계속 깜박이게 하지 않는다. 다음 음절이 시작되어 길이가 1 늘 때만 효과가 새로 생긴다.
- **타자기 모드**(v2.25.0): 글을 칠 때마다 같은 프레임에 `scroll_to_rect`로 스크롤한다. 직접 그리는 커서·덮개도 같은 `galley_pos`를 쓰면 어긋나지 않는다. 시험할 때 타자기 모드를 켠 상태도 확인한다.
- 문서를 바꾸거나 `apply_body_edit`처럼 코드가 본문을 바꾸면(예: `[[` 후보 확정) 효과·위치 상태를 초기화한다(옛 위치에서 미끄러져 오지 않게).
- 휴지통 문서(`self.cur_trashed`)처럼 편집이 안 되는 상태나 편집창에 포커스가 없을 때는 커서를 그리지 않는다.

## 6. 조심할 점
- 빠르게 칠 때 커서가 글자보다 늦게 따라오면 미끄러지는 시간을 줄인다(0.08초 → 0.05초).
- 마우스 클릭·페이지 이동처럼 멀리 옮길 때는 짧게(또는 바로) 이동해도 된다.
- `akashic.exe`가 실행 중이면 `cargo build`가 파일 잠금으로 실패한다. 먼저 종료하거나 `cargo test --release`로 컴파일을 확인한다. 확인용 실행은 시험용 폴더로: `$env:AKASHIC_DATA = "$env:TEMP\akashic-test-data"`.
- 사용자 문서 저장소(`%AppData%\Akashic`)는 건드리지 않는다.

## 7. 확인
- `cargo test --release` 전체 통과.
- 화면 확인은 사람이 앱에서 한다: 끔일 때 기존과 똑같음 / 깜박임 끄기 / "커서만"에서 글을 치면 막대가 부드럽게 따라옴 / 한글 조합 중에 번쩍이거나 흔들리지 않음 / 줄바꿈·클릭 이동이 어색하지 않음 / "커서+글자"에서 새 글자가 스며듦 / 표·코드 블록 안에서 깨져 보이지 않음 / 타자기 모드와 함께 써도 어긋나지 않음 / 가만히 둘 때 CPU가 오르지 않음 / 스크롤 중 커서 위치가 맞음.
- 사람이 확인하지 못한 항목은 DEVLOG에 "미확인(화면)"으로 적는다.
