# 타이핑 효과 구현안 (다른 Claude가 이어서 작업하기 위한 문서)

프로젝트: `E:\claude_work\akashic-rs` (Rust + eframe/egui 0.37 + rusqlite, Windows). 답변·주석·화면 글은 **한국어**.
커밋·푸시·버전 올리기는 사용자가 말할 때만 한다. 작업 전에 방식을 먼저 말하고, 코드 수정은 그 뒤에 한다.

## 1. 무엇을 만드나
편집창(본문)에서 글을 칠 때 두 가지 효과를 준다. 옵션으로 끄고 켠다.

1. **부드러운 커서**: 커서(캐럿)가 한 칸씩 툭툭 튀지 않고, 이전 위치에서 새 위치로 약 70~90ms 동안 미끄러지며 따라간다. 깜박임은 켜짐/꺼짐이 딱딱하게 바뀌지 않고 서서히 흐려졌다 선명해진다.
2. **글자가 스며드는 효과**: 새로 친 글자가 약 120ms 동안 투명하게 시작해 선명해진다.

사용자가 원한 이유: 한글을 조합할 때 커서가 번쩍거리는 것이 보기 싫고, 효과를 켜 두면 볼만하다고 했다. 둘 다 하고 싶다고 했다.

## 2. 정해진 결정 (바꾸지 말 것)
- 옵션 이름: "타이핑 효과", 선택지 **끔 / 커서만 / 커서+글자**. **기본값은 "끔"**(사용자가 켜 보고 느낌을 알려 주면 조정).
- egui 기본 커서는 숨기고 우리가 직접 그린다. egui에는 커서 이동 애니메이션이 없고 이를 해 주는 라이브러리도 못 찾았다. **새 크레이트를 추가하지 않는다**(의존성 규칙: 직접 의존성 10개 이하).
- 글자 효과는 **글자 배치를 다시 계산하지 않는다**. 새로 친 글자 위에 편집창 배경색 사각형을 덮고, 그 투명도를 100%에서 0%로 줄이는 방식이다. (글자별 투명도를 배치에 넣으면 큰 문서에서 매 프레임 다시 배치해 느려진다.)
- 표·코드 블록 안, 그리고 배경색이 편집창과 다른 곳에서는 글자 효과를 건너뛴다(색이 어긋나 보임).
- 화면을 다시 그리게 하는 것(`ctx.request_repaint()`)은 **애니메이션이 진행되는 동안만** 한다. 가만히 있을 때 CPU를 쓰지 않는다.

## 4. 순수 함수 설계 (`src/typefx.rs`)
화면 없이 시험할 수 있게 시간·위치를 인자로 받는다.

```rust
/// 커서 위치 따라가기. 지수 감쇠로 목표에 다가간다.
pub struct CaretAnim { pub pos: egui::Pos2, pub target: egui::Pos2, pub height: f32 }
impl CaretAnim {
    /// dt 초 흐른 뒤의 위치로 갱신하고, 아직 움직이는 중이면 true.
    /// - 줄이 바뀌었으면(목표의 y가 달라졌으면) 미끄러지지 않고 바로 이동한다.
    /// - 목표와 0.5px 안이면 목표에 붙이고 false.
    pub fn step(&mut self, dt: f32, tau: f32) -> bool;
}
/// 깜박임: 마지막 입력 후 시간 t(초)로 커서의 선명도 0.0~1.0. 입력 직후 0.5초는 항상 1.0(타이핑 중에는 깜박이지 않음).
pub fn blink_alpha(since_input: f32) -> f32;
/// 글자 효과: 글자를 친 뒤 경과 시간 age(초)로 덮개 투명도 1.0 → 0.0 (120ms).
pub fn reveal_cover(age: f32) -> f32;
```
시험으로 확인할 것: 줄 바뀜은 즉시 이동 / 거리가 먼 이동도 끝내 목표에 도달 / `step`이 멈추면 false / `blink_alpha`는 입력 직후 1.0이고 범위를 벗어나지 않음 / `reveal_cover`는 0초에 1.0, 120ms 이후 0.0.

## 5. 화면 연결 방법 (`body_editor`)
이미 있는 값들을 쓴다.
- `out.galley`, `out.galley_pos`: 글자 배치와 그 화면 위치. 커서 사각형은
  `out.galley.pos_from_cursor(egui::text::CCursor::new(idx)).translate(out.galley_pos.to_vec2())` (같은 함수가 이미 `scroll_to` 처리에 쓰임).
- 커서 글자 위치: 이미 `self.cursor_idx`가 `out.cursor_range`의 `primary`로 갱신됨(2570줄 부근).
- 한글 조합 상태: `self.body_composing`. egui는 **조합 중인 글자를 본문에 넣고 그 구간을 선택으로 잡는다**. 그래서 조합 중에는 선택 끝(primary)을 커서로 본다.
- 편집창 배경색: `ui.visuals().extreme_bg_color`(`bg` 변수로 이미 잡혀 있음).

순서:
1. 효과가 "끔"이면 아무것도 하지 않는다(기본 동작 그대로).
2. 효과가 켜져 있으면 egui 기본 커서를 숨긴다. `TextEdit` 그리기 직전에 `ui.visuals_mut().text_cursor.stroke = egui::Stroke::NONE`처럼 편집창 영역 안에서만 바꾼다(다른 입력칸의 커서에 영향이 없게 범위를 좁힌다). `egui::Visuals::text_cursor`의 정확한 필드명은 `E:\rust\cargo\registry\src\index.crates.io-1949cf8c6b5b557f\egui-0.37.0\src\style.rs`(1060줄 부근)에서 확인한다.
3. `TextEdit` 결과를 받은 뒤: 목표 위치를 갱신하고 `CaretAnim::step(dt, tau)` 호출(`dt`는 `ctx.input(|i| i.unstable_dt)`), 편집창에 포커스가 있고 선택이 없을 때만 막대를 `ui.painter()`로 그린다(폭 약 1.5px, 색은 기존 커서 색 `ui.visuals().text_cursor.stroke.color`).
4. 아직 움직이는 중이거나 깜박임 구간이면 `ctx.request_repaint()` 또는 `request_repaint_after`.
5. 글자 효과(2 선택 시): 본문 길이가 늘었고 커서가 그만큼 오른쪽으로 옮겨졌으면 "방금 친 글자 범위"를 목록에 `(시작, 끝, 시각)`으로 넣는다. 그릴 때는 각 글자의 사각형 위에 `bg` 색 사각형을 `reveal_cover` 투명도로 덮고, 0이 되면 목록에서 뺀다. 붙여넣기처럼 한꺼번에 많이 들어온 경우(예: 20자 초과)나 표·코드 블록 안은 효과를 건너뛴다.
6. 문서를 바꾸거나 `apply_body_edit`처럼 코드가 본문을 바꾼 경우에는 효과·위치 상태를 초기화한다(옛 위치에서 미끄러져 오지 않게).

## 6. 조심할 점
- 빠르게 칠 때 커서가 글자보다 늦게 따라오는 느낌이 나면 `tau`를 줄인다(0.03초 안팎에서 시작).
- 줄바꿈·페이지 이동·마우스 클릭으로 멀리 옮길 때는 미끄러지지 않고 바로 이동(또는 아주 짧게).
- 스크롤하는 중에도 커서가 제자리에 보여야 한다(화면 좌표는 `galley_pos` 기준으로 매 프레임 다시 계산).
- 휴지통 문서(`self.cur_trashed`)처럼 편집이 안 되는 상태에서는 그리지 않는다.
- 이 PC에서 `akashic.exe`가 실행 중이면 `cargo build`가 파일 잠금으로 실패한다. 컴파일 확인은 `cargo test --release`로 한다.
- 빌드는 약 4분 걸린다. 확인용 실행은 시험용 폴더로: `$env:AKASHIC_DATA = "$env:TEMP\akashic-test-data"` 후 `target\release\akashic.exe` 실행.
- 앱 안에서 쓰는 사용자 문서 저장소(`%AppData%\Akashic`)는 건드리지 않는다.
