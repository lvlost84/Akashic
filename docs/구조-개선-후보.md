# 구조 변경이 필요한 개선 후보 (2026-11-25 코드 리뷰)

haiku 에이전트 8개로 전체 코드를 리뷰하고, 지적 사항을 코드와 대조해 확인했다. 국소 수정으로 끝나는 것은 이미 반영했고, 아래는 여러 모듈의 관계나 구조가 바뀌어야 해서 따로 남긴 항목이다. 아직 코드는 바꾸지 않았다.

## 구조 변경 항목

| # | 위치 | 문제 | 필요한 변경 |
|---|------|------|-------------|
| 1 | docsync.rs `read_batch`, 동기화 루프 | 한 기기의 로그가 복호화 실패·형식 오류로 영구히 못 읽히면 `pull_err`가 남아 올리기가 매번 건너뛰어진다 | 일시 오류(네트워크)와 영구 오류(복호화·형식)를 구분하는 오류 타입 도입. 영구 오류는 그 로그를 격리하고 `Report`에 경고로 남긴다 |
| 2 | docsync_ui.rs 20분 초과 처리 | 시간 초과 시 수신 채널만 버리고 작업 스레드는 계속 돈다. `ds_busy()`가 풀려 두 동기화가 같은 DB·서버를 동시에 쓴다 | 취소 토큰(`Arc<AtomicBool>`)을 `docsync::sync` 단계마다 확인. 스레드가 끝나기 전에는 새 동기화 금지 |
| 3 | docsync_ui.rs `ds_after` | 병합 기준이 시작 시점 스냅숏 하나뿐이라, 동기화 중 자동저장이나 문서 전환이 있으면 기준이 어긋나 불필요한 충돌 사본이 생기거나 입력이 사라질 수 있다 | 문서별 기준본을 DB에 보관해 병합 기준으로 쓰거나, 동기화 중 해당 문서 저장을 잠근다 |
| 4 | vault.rs `FolderRemote::put`, sync.rs 잠금 | 폴더 백엔드의 조건부 쓰기가 비교와 교체 사이에 원자적이지 않다. 클라우드 폴더를 두 기기가 같이 쓰면 저장본이 지워질 수 있다 | 서버 측 CAS가 있는 백엔드(WebDAV)로 한정하거나, 충돌 사본을 감지하는 프로토콜 변경 |
| 5 | vault.rs `push_snapshot` | 세대 번호가 초 단위라 두 기기가 같은 초에 올리면 확정된 조각을 덮어쓸 수 있다 | 조각을 `IfNoneMatch`로 올리고 충돌 시 세대 번호를 올려 재시도(4번과 함께 설계) |
| 6 | webdav.rs 약한 ETag 처리 | HEAD 확인과 PUT 사이가 원자적이지 않고, `If-Unmodified-Since`에 +1초를 더해 같은 초의 다른 기기 쓰기가 통과할 수 있다 | 연결 시험에서 약한 ETag 서버를 거부하거나 WebDAV LOCK 사용 |
| 7 | mcp.rs `update_document`, `append_to_document` | 읽기와 저장이 따로라, 그 사이 GUI 저장이 옛 본문으로 덮어써질 수 있다(되돌리기 기록에는 남는다) | db.rs에 제목만 바꾸기, 본문 덧붙이기 같은 단일 SQL 함수 추가. `save_doc`의 부가 동작(auto_index 등)을 보존해야 한다 |
| 8 | md.rs, editkeys.rs, app.rs, mdhtml.rs | 코드 울타리 판정이 곳마다 다르다. 렌더링은 ```만, 일부 링크 판정과 `respace`는 `~~~`도 본다 | 먼저 `~~~`를 지원할지 결정하고, 판정 함수를 한 곳(`md`)에 두고 모두 그것을 쓴다 |
| 9 | mdhtml.rs ↔ md.rs | 화면용과 내보내기용 파서가 펜스·목록·수식·표 규칙을 따로 구현한다. 내보내기에서 목록 항목의 이어지는 줄이 사라지는 문제도 여기서 나왔다 | `mdhtml`이 `md::scan_blocks` 결과를 재사용. 출력 계약이 바뀌므로 내보내기 스냅샷 테스트 필요 |

## 사용자 결정이 필요한 항목

- **UNC 경로 링크** (`link_ui.rs`, `md::local_path`): **현행 유지로 결정(2026-11-25, 이슈 #18 닫음).** `[[\\서버\공유\…]]`를 확인 없이 탐색기로 여는 동작은 의도된 설계이며 그대로 둔다. 동기화·가져오기로 들어온 문서의 링크를 클릭하면 NTLM 해시가 나갈 수 있다는 위험은 알려진 상태다.
- **가져오기의 그림 경로** (`import.rs` `rewrite_image_lines`): 마크다운 안의 절대 경로나 `../` 경로가 가리키는 로컬 그림을 그대로 읽어 볼트에 넣는다. 정상적인 가져오기에서 쓰이는지 확인한 뒤 문서 폴더 밖 경로를 막을지 정한다.

## 국소 수정이지만 이번에 적용하지 않은 항목

- 동기화 임시 스냅숏 이름이 PID만 써서 중단된 옛 작업과 충돌할 수 있다(sync_ui.rs). 나노초나 카운터를 넣으면 된다.
- 진행 중인 동기화가 있는데 동기화 방식·폴더를 바꿀 수 있다(sync_ui.rs).
- 상태바 WebDAV 확인이 폴더 방식의 15초 제한을 그대로 쓴다(status_ui.rs).
- 창 닫을 때 WebDAV 올리기를 UI 스레드에서 기다린다(sync_ui.rs).
- 동기화 대기열 취소 후 `UploadLock`이 같은 기기의 새 잠금을 지울 수 있다(sync.rs).
- 첨부 임시 폴더 `%TEMP%\Akashic-files`를 지우는 코드가 없다(attach_ui.rs).
- 그림 처리 대기열에 문서 id가 없어 문서를 옮기면 남은 그림이 다른 문서에 들어간다(image_ui.rs).
- 글꼴 폴더가 `C:\Windows\Fonts`로 고정되어 있다(theme.rs). `WINDIR`을 쓰면 된다.
- mdhtml.rs 목록의 이어지는 줄 손실(내보내기), mdhtml.rs 인용·목록 재귀에 깊이 제한 없음.
- docsync.rs: DB 오류를 `.ok()`로 삼키는 `tomb_get`, `trace(format!(…))`가 릴리스에서도 평가됨, 누락된 그림·첨부를 조용히 건너뜀.
