# 구조 변경이 필요한 개선 후보 (2026-11-25 코드 리뷰)

haiku 에이전트 8개로 전체 코드를 리뷰하고, 지적 사항을 코드와 대조해 확인했다. 국소 수정으로 끝나는 것은 이미 반영했고, 아래는 여러 모듈의 관계나 구조가 바뀌어야 해서 따로 남긴 항목이다. 아직 코드는 바꾸지 않았다.

## 구조 변경 항목

| # | 위치 | 문제 | 필요한 변경 |
|---|------|------|-------------|
| 1 | (해결, 이슈 #10) | 읽을 수 없는 원격 로그가 올리기를 영구히 막았다 | **반영(2026-11-25):** 묶음 읽기 실패를 일시 오류와 읽을 수 없음(복호화·형식·이름 불일치)으로 나눴다. 같은 로그를 3번 연속 읽지 못하면 건너뛰고 `Report.skipped_logs`로 알린다(덜 받은 파일 같은 일시적 경우를 거르려고 여러 번 본다). 체크포인트가 손상되면 더 오래된 체크포인트로 넘어간다. 건너뛴 로그의 변경은 다른 기기가 체크포인트를 올리면 채워진다 |
| 2 | (해결, 이슈 #11) | 문서 동기화 20분 초과 시 작업 스레드가 계속 돌았다 | **반영(2026-11-25):** `Opts`에 취소 표시를 넣어 `docsync::sync`가 안전한 지점마다 확인한다. 20분이 지나면 UI가 취소를 요청하고, 스레드가 끝날 때까지 `ds_busy()`가 참이라 새 동기화는 시작되지 않는다. 올리기까지 끝난 뒤의 취소는 성공으로 마치고 기기 파일·체크포인트·정리만 건너뛴다. 서버 요청 하나가 진행 중이면 그 요청이 끝나야 반영된다(최대 180초) |
| 3 | (해결, 이슈 #12) | 동기화 중 저장·문서 전환 때문에 병합 기준이 어긋났다 | **반영(2026-11-25):** 문서 동기화가 도는 동안 `flush()`가 DB에 쓰지 않고, 편집 내용은 화면에 그대로 둔다. 끝나면 합친 뒤의 내용을 바로 저장한다(동기화 시작 때 찍은 스냅숏이 병합 기준으로 유지된다). 그동안 저장 안 된 편집이 있으면 다른 문서로 이동·휴지통 보내기가 막히고 안내가 나온다. 창을 닫을 때는 첫 시도를 막는다 |
| 4 | (일부 해결, 이슈 #13) | 폴더 백엔드의 조건부 쓰기가 원자적이지 않다 | **일부 반영(2026-11-25):** 폴더 백엔드의 "없을 때만 쓰기"는 하드 링크로 만들어 같은 PC의 다른 프로세스가 끼어들어도 놓치지 않는다(하드 링크가 안 되는 드라이브는 이름 바꾸기로 대신). 서로 다른 PC가 클라우드 동기화 폴더를 공유하는 경우와 manifest `IfMatch`의 비교-교체는 파일 시스템 수준에서 원자성을 보장할 수 없어 그대로다 |
| 5 | (해결, 이슈 #13) | `push_snapshot`의 세대 번호가 초 단위라 같은 초에 올리면 확정된 조각을 덮어썼다 | **반영(2026-11-25):** 조각을 `IfNoneMatch`로 올리고, 부딪히면 이번 시도에서 올린 조각만 지운 뒤 세대 번호를 올려 처음부터 다시 올린다(최대 8번). 남이 확정한 조각은 덮어쓰지 않는다 |
| 6 | (해결, 이슈 #14) | 약한 ETag 서버에서 manifest 조건부 쓰기가 원자적이지 않았다 | **반영(2026-11-25):** 약한 ETag를 받은 `IfMatch` 쓰기에서 서버가 WebDAV 잠금(LOCK)을 지원하면 파일을 잠근 채로 확인하고 올린다(만료 60초, 끝나면 UNLOCK, 다른 기기가 잠갔으면 423을 충돌로 처리). 잠금이 안 되는 서버는 기존 HEAD 비교와 `If-Unmodified-Since`로 되돌아간다. 시놀로지 WebDAV는 `DAV: 1,2`와 `LOCK, UNLOCK`을 알린다(2026-11-25 확인). 실서버 동기화로 한 번 확인이 필요하다. 조각 파일 덮어쓰기(#13)는 별개다 |
| 7 | (해결, 이슈 #15·#20) | MCP 수정이 읽기와 저장 사이, 또는 앱에서 편집하는 동안 GUI 저장분과 서로 덮어썼다 | **반영(2026-11-25):** MCP 쪽은 `db.save_doc_if`(제목·본문이 읽은 값과 같을 때만 바꾸는 한 문장짜리 비교-후-쓰기)를 써서 그 사이 바뀌었으면 새로 읽어 다시 한다(최대 5번). 앱 쪽은 문서를 읽거나 저장할 때마다 기준값(`App.base`)을 기억하고, 저장 직전에 DB와 비교해 밖에서 바뀌었으면 줄 단위 3-way 병합을 한다(겹치면 편집 중인 내용을 두고 바깥 내용은 '충돌' 사본으로 남김). 문서를 새로 불러오는 모든 경로(열기·저장·MCP 재로드·인덱스 재로드·이력 되돌리기·동기화 후 반영)에서 기준값을 갱신한다 |
| 8 | (해결, 이슈 #16) | 코드 울타리 판정이 모듈마다 달랐다 | **반영(2026-11-25):** CommonMark·GFM처럼 ``` 와 ~~~ 를 모두 울타리로 보고, 판정을 `md::fence_marker`·`md::is_fence_line` 한 곳으로 모았다. 코드 블록을 그리는 `scan_blocks`는 여는 표지와 같은 표지로만 닫는다. 줄 단위로 켜고 끄는 단순 판정(제목·위키 링크·이어쓰기 등)은 표지를 구분하지 않아, ``` 블록 안의 ~~~ 줄처럼 표지가 섞인 드문 경우는 근사다 |
| 9 | (해결, 이슈 #17) | 화면용 md.rs와 내보내기용 mdhtml.rs가 블록 규칙을 따로 구현했다 | **반영(2026-11-25):** 코드·표·수식·그림·가로줄의 경계는 `md::scan_blocks`가 정하고 `mdhtml`은 그 구간을 HTML로 바꾼다. 제목·가로줄·목록 판정은 `md::heading_parts`·`is_hr`·`list_marker_len`을 쓰고, 여러 줄 수식의 짝 찾기는 `md::math_fence_end`를 둘이 함께 쓴다. 인용·목록 묶기·문단은 `mdhtml`이 직접 읽는다. 목록 아래 들여쓴 줄·코드가 사라지던 문제도 함께 고쳤다. 화면 규칙을 따르므로 `#태그` 줄은 제목, `1)` 형식은 목록이 아니다 |

## 사용자 결정이 필요한 항목

- **UNC 경로 링크** (`link_ui.rs`, `md::local_path`): **현행 유지로 결정(2026-11-25, 이슈 #18 닫음).** `[[\\서버\공유\…]]`를 확인 없이 탐색기로 여는 동작은 의도된 설계이며 그대로 둔다. 동기화·가져오기로 들어온 문서의 링크를 클릭하면 NTLM 해시가 나갈 수 있다는 위험은 알려진 상태다.
- **가져오기의 그림 경로** (`import.rs` `rewrite_image_lines`): **폴더 밖 경로 차단으로 결정·반영(2026-11-25, 이슈 #19 닫음).** 가져오려고 고른 폴더(`Scan.root`) 밖을 가리키는 절대 경로나 `../` 그림은 읽지 않고 원문 그대로 둔다. 폴더 안의 `../attachments/x.png` 같은 상위 폴더 참조는 계속 허용하며, 링크는 풀어서 비교한다.

## 국소 수정이지만 이번에 적용하지 않은 항목

- 동기화 임시 스냅숏 이름이 PID만 써서 중단된 옛 작업과 충돌할 수 있다(sync_ui.rs). 나노초나 카운터를 넣으면 된다.
- 진행 중인 동기화가 있는데 동기화 방식·폴더를 바꿀 수 있다(sync_ui.rs).
- 상태바 WebDAV 확인이 폴더 방식의 15초 제한을 그대로 쓴다(status_ui.rs).
- 창 닫을 때 WebDAV 올리기를 UI 스레드에서 기다린다(sync_ui.rs).
- 동기화 대기열 취소 후 `UploadLock`이 같은 기기의 새 잠금을 지울 수 있다(sync.rs).
- 첨부 임시 폴더 `%TEMP%\Akashic-files`를 지우는 코드가 없다(attach_ui.rs).
- 그림 처리 대기열에 문서 id가 없어 문서를 옮기면 남은 그림이 다른 문서에 들어간다(image_ui.rs).
- 글꼴 폴더가 `C:\Windows\Fonts`로 고정되어 있다(theme.rs). `WINDIR`을 쓰면 된다.
- mdhtml.rs 목록의 이어지는 줄 손실(내보내기), mdhtml.rs 인용·목록 재귀에 깊이 제한 없음.
- docsync.rs: DB 오류를 `.ok()`로 삼키는 `tomb_get`, `trace(format!(…))`가 릴리스에서도 평가됨, 누락된 그림·첨부를 조용히 건너뜀.
